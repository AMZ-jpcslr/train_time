# 現在地から駅入口までの徒歩計算

確認日: 2026-10-22（Asia/Tokyo）。外部の歩行者用経路から所要時間を計算するローカル試作接続です。実測時間の入力は位置情報を使えない場合の代替として残しています。

後続のVercel対応では、全インスタンスに共通する回数・同時数制限をRedisに追加しています。連絡先・公開URL・Redisの設定と公開時の確認事項は [Vercel公開手順](deployment-vercel.md) を参照してください。以下のプロセス内制限の説明はローカル起動時のものです。

## 接続・利用条件

- 提供者: FOSSGIS、OSRM `routed-foot` サーバー。`/routed-foot/route/v1/foot/` を使用。公式[サービス説明](https://routing.openstreetmap.de/about.html)、[実際の提供プロファイル](https://github.com/fossgis-routing-server/osrm-frontend/blob/master/src/leaflet_options.js)、[徒歩プロファイル](https://github.com/fossgis-routing-server/cbf-routing-profiles/blob/master/foot.lua)を確認しました。自動車プロファイルは使用しません。
- [全文利用条件](https://www.fossgis.de/arbeitsgruppen/osm-server/nutzungsbedingungen/)は通常HTTPSで取得・確認済み（`.cache/routing/fossgis-terms.html`）。無料データと無料サービスを区別し、帰属・地図修正リンク・運営者メール・識別User-Agent・同時接続制限・最大1要求/秒を確認しました。高トラフィック・大量取得・事業の中心となる商用利用を認める契約ではありません。
- ローカル試用では直列取得、1.1秒以上間隔、30回/時・120回/日起動プロセス内上限、同一要求の集約、10分間のメモリーキャッシュ、20秒タイムアウト、429/5xx時のバックオフを実装。カウントダウンでは再取得しません。公開・本番用の無制限APIとして使用しません。全般的な可用性の保証はありません。
- ユーザーが指定した連絡先を `.env.local` の `ROUTING_CONTACT_EMAIL` に保存し、アプリにメールリンクを表示します。`.env.local` はGit管理対象外。新しい環境では `.env.example` を参考に設定してください。設定がない場合、公開経路サーバーへの要求を止めます。メール送信・アカウント登録はありません。
- URLは `ROUTING_FOOT_URL` で変更できます。自前のOSRMなら**徒歩プロファイルで生成した道路データ**が必要です。URL末尾にfootを付けるだけで自動車グラフが徒歩になるわけではありません。

## 位置情報と到着地点

「現在地を更新」を押したときだけブラウザーの位置情報許可を求めます。取得した緯度経度と選択した駅入口を、ローカルAPI経由でFOSSGISへ送ります。アプリは現在地履歴をディスク/localStorageへ保存せず、経路キャッシュはサーバーのメモリーだけです。提供先のアクセスログに位置が記録される点を操作ボタン付近に表示します。

`src/data/entrances.json` は11駅22入口。OSMの明示的な駅入口タグ、駅名付き入口、駅舎外周と歩道への接続から20点を選択。学園都市は駅探の出口地図に掲載された北・南出口2点で、駅中心から推測した点ではありません。詳細は [入口資料](entrance-sources.md)。商業施設入口・他社の地下鉄入口・臨時出口・確認できた時間制限付き西出口を採用していません。全入口の現地測量・営業時間・バリアフリー可否を保証するものではありません。

先頭の入口は直線距離で近い候補です。全入口への最短経路比較を行う機能ではなく、ユーザーが入口を選び直せます。現在地が駅から25km超、精度100m超、取得から5分超の場合は自動判定を使いません。駅ビルの入口から改札・ホームまでの時間は設定値として別加算します。大きな駅では実際に使うホームまでの時間に調整してください。

## 計算と失敗時の挙動

歩行経路の距離・所要秒数・shape・各stepのwalkingモードを検証します。直線距離の代用、ferryやdrivingなどの混入、入口/現在地から30mを超える道路への補正、異常な距離は拒否。30m以下の端点の補正距離も歩行時間へ加算します。地図の少量の補正区間が実際に通行可能かは保証しません。

FOSSGISの既定歩行速度4.5km/hと利用者設定速度（1〜6km/h）を使い、`max(提供所要秒数 × 4.5 / 設定速度, 経路距離 / 設定速度)`を分へ換算し切り上げます。経路の形状を地図背景なしの図で示し、OSMの歩行経路地図へのリンクも用意します。図自体は道案内地図ではありません。階段・信号・混雑・工事・入口開閉の実時間は保証できません。

駅変更・入口変更・位置更新・精度悪化・位置の期限切れ時は、前の経路を次の駅の判定に流用しません。取得中は判定不可、拒否/NoRoute/NoSegment/通信失敗/オフラインは理由を表示。保存済み実測地点は明示選択時だけ代替使用できます。

## 再現・検証

```powershell
# 既存入口原資料の再解析（ネット通信なし）
npm run data:entrances
# OSMの小範囲入口データを明示的に更新（高頻度で繰り返さない）
node scripts/fetch-entrances.mjs --refresh
# 更新後は名称・駅舎・タグ・通行制限を確認してから再解析
npm test -- tests/walking.test.ts
```

`scripts/reviews/gakuentoshi-entrances.json` は独立確認済み資料のSHAと入口を結び付けます。原資料が変われば無確認で再採用せず、出口名称とWGS84座標の対応を再照合します。編集用OSM APIは調査時の少数readのみで、アプリ・更新経路には使用しません。OSM更新の標準経路はread-onlyのOverpassです。

[実経路検証](routing-live-validation.json)には検証用の公開駅近傍座標、成功・失敗をそのまま記録。本人の現在地ではありません。E2EではGPSと経路応答を固定し、表示・判定・失敗遷移を検証します。実際に歩いた所要時間や乗車成功の実証とは区別しています。
