# 文言レビューと統一方針（2026-10-26）

この表は現コードを読んだ文言監査と、操作プレビューへの適用範囲を記録する。利用者のB案選択後、通常UIへ反映した。上表の提案と後半の実適用記録を区別する。現行比較は `?design=baseline`、提案は `?design=board|action|favorites`。設定、通知、初回の位置取得、ホーム画面追加も確認対象とした。既存の通知・位置取得・インストール処理を試作で実装済みと扱わない。

## 表記をそろえる

- 利用者の判断には「出発目安」。操作不能の理由は「計算できません」と理由・次の操作を併記。「乗車可否」は文書の技術的説明に限る。乗車成功の保証はしない。
- 発車時刻は `14:14 発`、出発目安は `14:03 まで`、所要時間は `徒歩8分 ＋ 構内・余裕3分`。秒のカウントダウンを主要情報にしない。24:xxは前の運行日の時刻であることを併記。
- 「構内・余裕」は入口からホームへ移動し、乗車までに確保する時間。現行計算はこの1項目に余裕を含む。別枠の余裕を追加したような表示はしない。
- 「当日」は画面の選択運行日。実時計によるデータ確認期限と、指定日時のプレビューを分ける。
- 「出典照合済み」は記録した範囲での照合。全駅全便・臨時便・現場の安全性を証明した意味にしない。
- カタログを「検索できる」、ファイルを「取得済み」、確認記録を「照合済み」、日付・鮮度を「当日の利用」、徒歩条件を含む結果を「出発目安」と呼び分ける。
- 方面は駅の選択条件、行先は便ごとの終着。両者を混ぜない。未収録の番線・行先を推測しない。

## 状態表示の実装上の境界

プレビュー上部の状態切替は、失敗・拒否等の再現例であり、外部API通信や端末権限の変更を実行しない。「もう一度読み込む（比較）」は通常状態へ戻すだけで、取得成功を報告しない。実際の通信失敗・位置拒否・JR期限・保存・PWA動作は既存アプリの回帰テストで別に確認する。

B選択後、既存の取得hook、位置情報の同意前説明、実測地点保存、設定・更新・初回案内を統合した。上表は比較時の提案であり、最終的な採用語は次の実適用表とコードを正とする。比較用の時刻・徒歩値・simulationは通常の利用フローへ持ち込まない。

## B案採用後：共通部品への適用

利用者のB「出発目安」案の選択を受け、次を通常画面の共通部品へ適用した。画面本体の統合と分けて、操作名・通信・権限・保存形式を維持している。

|対象ファイル|適用した変更|維持した境界|
|---|---|---|
|ChoicePicker / StationPicker|装飾的な英語見出しを除去。「駅を変更」、お気に入り保存の説明を短文化。追加検索の時刻表は非公式の参考情報で計算に使わないことを明記|駅・方面の選択、保存単位、既存の操作名・キーボード操作|
|InstallApp|宣伝的な英語と重複説明を除去。承認後は「アイコンがあるか確認してください」と案内|ブラウザ承認だけで導入完了と断定しない。端末別手順とWebアプリ／ウィジェットの区別|
|PwaUpdate / serviceWorkerUpdates|「アプリの更新」へ統一。時刻表の再取得と別操作と説明し、最後の「最新版に更新」で切り替わることを明記|通知は更新欄へ移動するだけ。「最新版に更新」「アプリの更新を確認」「タップして更新欄へ移動」は維持|
|LocationHelp / useGeolocation|誤差が大きい場合は取り直すか実測時間を使う、と対処を先に表示。端末別説明を展開内へ整理|100m以下の基準、最大20秒、取得中止、位置情報許可の設定説明|
|WidgetTransfer|英語装飾を除去し「ホーム画面ウィジェット」へ。専用アプリが必要なことを明示し、開発者向け導入案内は展開内へ移動|最大5便・最大6時間先・位置と時刻表の期限・背景更新の制約。保存ボタン名も維持|
|useWalking / useStationTimetables|通信失敗時の英語ブラウザ例外を日本語の原因と再操作へ変更。内容不整合は通信失敗と別メッセージ|取得失敗を未対応・終電後とは表現しない。検証条件やキャッシュ期限は変更しない|
|useWesternStations|「APIから追加」から「追加検索で見つかりました」へ。保存失敗を容量不足と決めつけず、設定消失の可能性を案内|参考情報である制約、検索中止、選択中の駅の保持|

文言変更に伴うテスト期待値の修正は、導入承認後の案内と追加検索の結果表示の2ファイルに限定した。この部品文言作業ではテストを単独実行していない。採用案統合後の全体検証結果を参照する。

|対象|通常画面の実適用|理由|

既存機能の操作名はテスト・利用習慣との整合上、提案をすべて機械的に置換していない。「端末に保存して使う」「この登録地点を削除」「最新版に更新」「入口からホームまで（分）」等は維持。設定直下に乗車までの余裕を含める説明を残す。保存失敗の説明も既存文を維持し、原因を容量不足などと推測しない。
