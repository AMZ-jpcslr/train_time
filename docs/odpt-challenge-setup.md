# チャレンジ2026の非公開トークンと認証データ

## ローカルでのトークン設定

Windowsのこの作業環境では、プロジェクトルートで `npm run odpt:setup` を実行します。出力された `http://127.0.0.1:.../setup/...` のURLをブラウザーで開き、チャレンジ2026専用トークンを入力して保存してください。「暗号化して保存しました」と表示されれば完了です。入力ページの有効期限は15分です。

入力用サーバーは127.0.0.1だけで待ち受け、推測困難な一時URL、Hostチェック、明示的な外部Originの拒否、外部スクリプト禁止、外部フレーム禁止、キャッシュ禁止を使います。Referrer-Policy:no-referrerで通常のフォーム送信もOrigin:nullになるため、この場合は192ビットの一時URLを検証して受け付けます。保存するとサーバーは終了します。入力の記録・表示・URLへの挿入は行いません。パスワード欄の値はコマンド引数にも環境変数にも載せず、子プロセスへの標準入力だけで渡します。

`scripts/odpt-token.ps1` がWindows DPAPIで暗号化し、`.cache/odpt-credentials/challenge2026.dpapi` に保存します。ディレクトリのアクセス許可は現在のWindowsユーザーだけに限定します。復号にも同じWindowsユーザーが必要です。この環境で利用可能な `pwsh.exe` を使い、Windowsの実行ポリシーを変更しません。

復号されたトークンはサーバープロセス内だけで利用します。`/api/config` は設定の有無・利用可否だけを返します。フロントのJavaScript、HTML、localStorage、Service Worker、Git、Redisキャッシュにトークンを含めません。トークンの変更後は開発サーバーを再起動してください。

## 取得と表示

対象はJR東日本、小田急、京急、相鉄、京王、東武、西武、東急の8事業者です。固定したODPTエンドポイントに対し、駅・路線・駅時刻表・列車種別・方面情報・必要な特別運行日カレンダーを取得します。1,000件の応答上限に達した駅・駅時刻表は、公開されている路線ごとに取得し直します。直通先の行先名は、参照された事業者の駅メタデータで解決します。利用者が指定したURLを代理取得する機能はありません。

認証が有効なときだけ、アプリが各事業者の駅一覧を順に取得し、既存の駅検索へ追加します。元の限定データや生成した時刻表を `public/`、`src/data/`、GitHubへ追加しません。時刻表は駅と運行日を指定してアプリのAPIから取得します。検索結果からの駅選択・お気に入り登録は既存と同じ操作です。

取得は事業者単位で同時要求をまとめ、原則1.1秒以上の間隔を空けます。ローカルでは`.cache/odpt-challenge/`に圧縮して保存します。サーバー取得キャッシュは6時間です。Vercelでは既存のRedis設定を使って圧縮データと取得ロックを共有し、共有キャッシュがない場合は認証データの外部取得を停止します。トークン付きURL、上流のエラー本文、外部通信エラーの詳細をAPI応答へ転送しません。

駅時刻表の元の平日・土曜・休日区分を使い、休日の判定には内閣府の祝日表を使います。京王の競馬場開催日など、ODPTの特別カレンダーが日付を明記している場合は、その日だけ特別ダイヤを通常表に優先します。特別カレンダーを確認できない場合は通常ダイヤで代用せず、取得を停止します。00:xx〜03:xxは前の運行日の24:xx〜27:xxとして扱い、秒付き発車時刻を保持します。12月29日〜1月3日の特別ダイヤは通常の曜日パターンから推測せず、今回の認証付きJSONアダプターでは表示を停止します。

元データにない駅入口、番線、行先名、列車種別は生成しません。行先・種別を参照できない場合は未確認と表示し、件数を対応範囲に記録します。同時刻・同じ行先の別列車は、元資料の列車番号を保持して選択を区別します。共有駅は元資料の駅時刻表への明示的なリンクを使い、駅名の類似だけで位置を推測しません。新規駅の徒歩判定には実測時間を登録してください。

## 本番用の設定

Vercel側ではサーバー専用の環境変数 `ODPT_CHALLENGE_TOKEN` に設定します。`VITE_` 接頭辞は付けません。Windows DPAPIのファイルはVercelへコピーせず、秘密情報として環境変数を設定する必要があります。設定後は再デプロイします。ソースコードや本番ビルドにトークンを直接埋め込まないでください。

今回の実装コードだけをデプロイしても、Vercel側にトークンが設定されていなければ認証データは有効になりません。ローカルの暗号化設定とVercelの設定は別です。

VercelのAPI転送は5つの公開エンドポイントを固定して指定しています。動的な名前付きパスはVercelによって検索パラメーターにも追加されるため、ODPT APIの厳密なパラメーター検証と衝突します。`/api/:path*` のような包括転送へ変更する場合は、この差を考慮した本番疎通確認が必要です。API側で不明な検索パラメーターを無条件に許容する対応は行っていません。[Vercelの転送設定](https://vercel.com/docs/project-configuration/vercel-json)

## 照合と確認

```powershell
# 実データを取得し、元データと全発車時刻の多重集合を独立照合
node scripts/check-odpt-challenge.mjs
# 架空データだけを使った認証・変換・キャッシュ・API境界のテスト
npx vitest run tests/odpt-challenge.test.ts
# PC・スマホ相当で検索・保存・読み込み失敗時の表示を確認
npx playwright test tests/e2e/odpt-challenge.spec.ts --workers=2
npm run build
npm run check:package
```

実データの照合結果は `.cache/verification/odpt-challenge-live.json`、原資料の圧縮保存は `.cache/odpt-challenge/*-source-*.json.gz` です。どちらもGit管理対象外です。テスト用フィクスチャは架空の駅・路線・時刻だけで、限定データや本物のトークンを含みません。

## 利用条件と対象範囲

提供条件は [チャレンジ限定ライセンスと特定利用条件](https://developer.odpt.org/challenge_license) を確認してください。再利用可能な形での元データ・復元可能な派生データの再配布には制約があります。JR東日本には競合サービスに関する特定利用条件もあります。トークン取得を、データの自由な再配布や用途全般の許可と扱いません。

提供期間の終了は2027-03-12です。APIとアプリは終了後の認証データ表示を停止し、Redisの保存期限も終了時刻までに制限します。ローカルの限定データキャッシュは、終了後にサーバーが起動・設定確認された際に削除します。PCが停止していた期間に常駐して削除を行う機能ではありません。

[JR東日本の提供範囲](https://ckan.odpt.org/dataset/jreast__r_station_timetable)は関東の一部の在来線のみで、新幹線、中央・青梅線の特急を含みません。常磐線は坂元以南、中央線は高尾以東が対象です。臨時列車・他路線直通列車などの一部を含まない場合があります。東京メトロなど通常のODPT用トークンが必要な提供分は、チャレンジ2026専用トークンだけでは取得しません。
