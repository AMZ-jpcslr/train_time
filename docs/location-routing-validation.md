# 位置・徒歩経路・操作画面の追加検証

確認日: 2026-10-22（Asia/Tokyo）。この変更は、位置情報の改善待ち、屋内からの道路接続、駅選択、現在地操作、出発まで滞在できる時間の目安を対象にしています。時刻表の収録範囲は11駅58表・11,400レコード、入口22点から変更していません。

## 変更した動作

- 利用者の操作で高精度の位置取得を開始し、最大20秒で終了します。最初の位置が粗い場合に改善を待ち、古い位置より新しい位置を優先。許可拒否・中止・画面離脱・古いコールバックを検査しています。位置取得中に経路APIを連続して呼びません。
- 位置精度の表示を「推定誤差 半径約○m」に変更。100mの判定基準は維持し、PCで精度が不足する場合の端末設定案内を追加しました。
- 徒歩サービスへ渡す道路探索範囲を30mから200mへ変更。1回の要求で探索し、取得に失敗した際の自動連打はありません。30mを超える接続は未確認として徒歩時間を概算表示し、乗車判定と滞在時間を停止します。
- 実際の現在地と道路上の接続位置を区別し、図の実線は道路経路、破線は直線の接続概算と表示します。接続距離は出発側・入口側それぞれ表示します。
- NoSegment、NoRoute、検索条件エラー、接続失敗を区別。手動再取得とGoogleマップの徒歩経路リンクを追加しました。Googleの検索結果を読み戻す実装や課金APIは使用していません。
- 駅選択を検索付きの独自ダイアログに変更。駅名・事業者・路線・駅コードを一緒に表示し、スマートフォンでは下から開くパネルにしています。矢印/Home/End/Enter、Esc、Tabの循環、選択後のフォーカス復帰を検証しました。
- 位置情報ボタンを発車案内の上へ移動。取得中・中止・推定誤差・位置情報の取り扱いも上部にまとめています。
- 先発について「今の場所にいられる目安」と出発時刻を表示。登録地点は名前と実測徒歩時間を使用し、現在地からの自動経路と区別します。徒歩・構内移動・安全余裕を引き、秒を切り捨てます。時刻ちょうど、過ぎた状態、位置の期限切れ、未確認接続を別の表示にします。

## 画面の設計

`frontend-design` スキルに沿って、電光掲示板と駅の操作盤を組み合わせた実用的な方向を選択しました。黒い面、緑の発車表示、駅コードの枠、事業者・路線を同時に読む選択行を共通要素にしています。DFIIは15（視覚的効果4 + 用途適合5 + 実装可能性5 + 表示負荷4 − リスク3）。これは設計時の評価で、利用者調査のスコアではありません。

Zen Kaku Gothic NewとBarlow CondensedをSIL OFL 1.1で同梱。画面文字のサブセットは合計194,756バイトで、通常実行時に外部フォントを取得しません。`scripts/update-fonts.mjs` がGoogle Fontsの公開配信から再生成し、OFL全文を保存します。通常のビルド・CIにはフォント取得通信はありません。フォントもPWAの保存対象です。

PC1280×720、スマートフォン390×664相当、狭幅320×640で確認しました。実画面の画像を確認し、上部位置ボタンがスクロール前に収まること、横はみ出しがないこと、選択パネルの操作を検証しています。画像はテスト用GPS・経路応答を使い、利用者の現在地や連絡先は含みません。Safari/iPhone/Android実機での追加確認は未実施です。

## JR茨木への実サービス確認

利用者のGPS座標は取得していません。[立命館大学の公式ストリートビュー案内](https://www.ritsumei.ac.jp/features/oicstreetview/)にある公開地点2点から、収録済みJR茨木の東西入口へ確認しました。うち1点は公開リンク「コンコース1F中央」です。

全8要求を直列に、2秒以上の間隔で実施しました。30mと200mの探索範囲を両方確認し、どちらも全件成功しています。したがって、入口が徒歩道路網へ接続することは確認しましたが、報告された端末・屋内位置のエラーそのものは再現できていません。探索範囲だけが原因だったとは断定していません。

|---|---|---:|---:|---:|
| 公式案内の公開地点 | 東側 | 722.4m | 577.7秒 | 580.4秒 |
| 同上 | 西側 | 754.3m | 603.2秒 | 605.9秒 |
