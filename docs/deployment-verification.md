## 変更した処理とテスト

`api/index.mjs` から共通APIハンドラーを起動し、Vercelの書込先を一時フォルダーと共有Redisへ変更した。ローカルのVite dev / previewは従来どおり利用できる。

- JRの指定日8表を検証してから共有キャッシュへ保存。取得時刻・有効期限・日付・内容の改変を検査する。
- 複数インスタンスの同時取得、異なる運行日の競合、ロック取得前後の競合、所有者の一致を検査する。失敗時はバックオフし、Redisがなければ外部取得しない。
- 徒歩サービスはRedisを使った同時数・要求間隔・時／日単位の上限と、429等の共有バックオフを持つ。RedisへGPS座標を渡していないことを検査する。
- APIの書換えパス、GET/POST、Vercel解析済みJSONとストリームJSON、不正日付、サイズ上限、異なるOrigin、秘密情報を含む例外を検査する。
- クラウド向けのUser-Agent・Referer、公開設定の内容、Redis疎通失敗時の停止を検査する。
- PC1280×720とスマートフォン390×664相当で設定不足・提供先・プライバシーリンクを確認する。実際の位置情報・経路応答はモックで、外部提供先へのアクセスは遮断する。

## 実行していない検証

Vercelへの登録・デプロイ、Redisサービスの作成・契約は行っていない。クラウド向けRedisテストはコマンド契約のテスト用実装であり、実RedisでのLua実行・実際の分散競合を保証するものではない。実VercelでのURL書換え、Functionの実行時間、Redisや時刻表・徒歩提供先への通信も未検証。[公開手順](deployment-vercel.md) のデプロイ後確認が必要。

GitHub ActionsにはLinux / Node 24で同じテスト・ビルド・Functionパッケージ検査を実行する `Check` を追加した。リモートでの最新結果は [Actions](https://github.com/AMZ-jpcslr/train_time/actions) を参照する。この文書の件数はローカル実行結果である。

原資料・秘密情報・連絡先を含む画面画像はGitから除外。時刻表の出典照合、実際の歩行APIを用いたローカル疎通、対象外の運行・権利条件は [既存の検証記録](verification.md) と [README](../README.md) を参照する。
