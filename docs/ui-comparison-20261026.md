# まにあう UI操作比較・B案採用

2026-10-26。現行画面を残し、情報構造の異なる3案を実装した。色だけを変えた比較ではない。比較提示後、利用者がB「出発目安を優先」を選択。通常画面へBの情報構造を組み込んだ。

## 開く

`npm run dev -- --port 5173` を実行し、次を開く。全て同じローカルアプリのURLで、公開・デプロイはしていない。

- [A 発車案内](http://127.0.0.1:5173/?design=board)
- [B 出発目安](http://127.0.0.1:5173/?design=action)
- [C いつもの駅](http://127.0.0.1:5173/?design=favorites)
- [変更前の比較用UI](http://127.0.0.1:5173/?design=baseline)
- [採用後の通常画面](http://127.0.0.1:5173/)

比較条件: 2026-10-26（月）14:00 JST、学園都市→三宮・新神戸・谷上方面、実測徒歩8分、入口から乗車まで3分（余裕を含む）。時刻は実際の同梱時刻表。3案では14:14発谷上行き、出発目安14:03・あと3分が初期候補。現行版の初期候補決定ロジックは変更せず残したため、14:06発が先に選ばれる。14:14発を手で選べば、同じ便の計算結果を比較できる。選択前のこの差自体も改善点として扱う。

比較用の時刻は固定、鮮度判定は実時計。期限を過ぎればプレビューも計算を停止する。既存のlocalStorageキー `mania-u:v1` は読み書きしない。3案の操作状態は別sessionStorageキー、現行比較はメモリーだけ。初期化は「状態を試す・比較について」→「同じ比較条件に戻す」。通常画面の実測地点・お気に入り・設定は保持される。

## 3案の狙いと判断

|項目|A 発車案内|B 出発目安|C いつもの駅|
|---|---|---|---|
|優先する情報|各便の発車時刻・行先・余裕を同じ列に|選択便とここを出る目安、その条件|保存した駅・方面から現在の案内へ|
|配色・文字|青灰色、線で区切った表、時刻列を固定|生成りと薄緑、出発時刻を最も大きく|暖色の地に茶系、駅名と方面を対で表示|
|配置|モバイルは一覧→選択便詳細、PCは横並び|選択便詳細→全便の横スクロール、PCは横並び|お気に入り→駅・方面→選択便と縦の便一覧|
|ボタン|便の行をそのまま選択|条件を表示したボタン、便カード|駅と方面の組を押す、一段で復帰|
|長所|近い便の時刻や行先を見比べやすい|出る時刻と発車時刻の区別がつきやすい|頻繁に複数駅を切り替えるときに少ない操作|
|弱点|モバイルでは詳細が下に回りやすい|多数の便の一覧性はAに劣る|上部の駅リストが出発目安を下へ押す|
|次の改善|一覧内から選択結果へ明確に移動|普段の駅への短い入口を維持|保存数が増えた際の折りたたみや順序|

**推奨はB。** 普段の駅で「今出ればどれに余裕を持って乗れそうか」という主要目的に最も直接対応する。選択便の発車と自分が出る時刻を一つの領域で読み、徒歩条件を1操作で確認できる。これは実装者による操作観察と情報配置の評価であり、ユーザーテストで有意に速いと証明した結果ではない。この比較を提示後、利用者の明示選択によりBを採用した。

## 通常画面への統合

Bの「選択便 → ここを出る時刻 → 計算条件」を通常画面へ採用。既存の位置取得・道路経路・実測地点・保存設定・お気に入り・PWA・出典表示を接続した。自分が出る時刻をHH:mmで大きく表示し、残り時間は分単位。判定自体は秒単位の境界を維持する。参考時刻・徒歩未確認から出発目安を算出しない。

初期候補は計算可能なら3分以上の余裕がある便を優先する。候補を選んだ後は毎秒勝手に変更しない。全運行日の横スクロール一覧を残し、時刻表の相対的な線路図は「時刻表の流れを見る」内へ移動。常時点滅を廃止し、動きを減らす設定に従う。

下部にお気に入り・駅と方面・徒歩時間への操作を置く。お気に入り選択後は主表示へ移動。既存の保存キーとデータ形式は保持する。登録地点を保存しても、再読込時には利用者がその地点にいることを選び直す。以前の場所にいると決めつけない。

比較専用の固定時刻や仮の徒歩時間は通常画面に持ち込まない。未採用のA/Cと旧UIは比較URLにだけ残し、通常画面に切替メニューを混在させない。旧UI比較は開始時の画面構造を残すが、共通部品の文言・新データは共有する。変更前ソースの厳密な保管先は `.cache/work-20261026-baseline/`。

通常画面の撮影は `adopted-{desktop,mobile}[-viewport].png`。画像は試験用実測地点「自宅・北口・8分」を登録し、時計を10/26 14:00へ固定した自動ブラウザ内で取得。ユーザーの実際の自宅情報でも位置測定でもない。動作確認の成否・制限は [統合報告](kansai-ui-review-20261026.md) を参照。
