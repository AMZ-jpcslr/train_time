# JR会社・路線単位の取得範囲宣言（2026-10-26）

新駅データを取得せず、現在のJR西日本4駅8方面を取得処理・サーバー・画面側で同じ宣言から検査する準備を実装した。新しい駅への対応拡充完了を意味しない。

## 変更した境界

`src/data/jr-scope.json` にJR西日本、公式出典origin、JR神戸線・京都線・琵琶湖線、既存4駅のID・EID・原表路線名・方面を宣言した。順序と値は従来の `JR_STATIONS` を維持する。

`src/domain/jr-scope.mjs` はNodeとブラウザーで共用できる検査・導出部分。会社／origin／版、空配列、ID・EID・方面の重複、未知沿線、沿線と原表路線名の不一致、未知フィールドを拒否する。検査後の実行時宣言を深くfreezeし、応答検査には新しいSetを返す。

- importerの `JR_STATIONS` は宣言から既存のtuple形式へ導出する。
- サーバーは宣言された全方面と一致する時刻表・証拠件数を要求する。
- ブラウザーも固定の手書き8ID一覧を持たず、同じ全方面を要求する。
- 件数が一致しても、駅ID・方面ID・事業者・路線名・方面名が宣言と違えば拒否する。サーバーではtable IDと駅・方面・運行日の組み合わせも一致させる。

`server/cloud-jr.mjs` は既存の `validateResult` を使用しているため、この完全性検査を共有する。別のクラウド用対象一覧は追加していない。

## 取得対象・品質確認・利用条件を分ける

宣言は次を別項目として保持する。

| 項目 | 現値 | 意味 |
| --- | --- | --- |
| acquisitionScope | existing | 現在の取得対象を保持する |
| qualityReview | docs/jr-validation.json | 保存済みの解析・時刻照合根拠 |
| reusePermission | unresolved-existing | 再利用条件の未解決を明示する |

品質確認済みというフラグを再利用許諾と解釈しない。`pending`・`approved` 等にフラグを変えて新規取得を解禁する経路は作っていない。未対応の状態や未知フィールドは黙って読み飛ばさず、宣言を拒否する。

この宣言はソース管理される設定で、ユーザー入力や外部APIから読み込まない。スキーマ検査は法的許可の証明にはならず、既存の構造を真似て駅を追記することも新規取得の承認にはならない。新駅の有効化は、利用条件の根拠・駅台帳・出典・方面／分岐／終端の検証を別途確認し、明示的にレビューした変更として行う必要がある。
