### 追加の対応付け根拠

従来の3条件に加え、**既存の鉄道入口ノードから、駅施設に所属するホームまたは照合済みの駅舎・駅地点へ、OSMの歩道・階段が明示的に接続する場合**を採用した。歩道は最大2本・経路長150m以内、通行制限・条件付き通行・工事区間を除外する。他社の駅施設グループだけに所属する入口や、別の入口を通り抜けて接続する場合は除外する。地図上で近いだけの入口、ホームの端・中心や駅代表点の入口化は行わない。

`osm.paths` が照合に使った歩道、`osm.feature` が接続先の駅施設。プラットフォームの座標は照合根拠だけで、徒歩APIの目的地は元の入口ノードの座標である。駅舎内の独立した `train_station_entrance` も、対応する駅舎の外形との包含関係を照合する。

`network` が「三田線」「大江戸線」等の路線名の場合に他社と判定していた取りこぼしも修正した。明示的な他社事業者名は引き続き拒否する。駅番号付き名称、`駅舎`・`駅出入口` の表記揺れも処理するが、京急川崎と川崎のような別駅の区別は保持する。

白金台は[東京メトロ公式の施設共用案内](https://www.tokyometro.jp/ticket/particularcase/meguro_shiroganetakanawa/index.html)と[公式出口案内](https://www.tokyometro.jp/station/shirokanedai/index.html)を照合し、東京地下鉄管理のOSM駅施設にある2番出入口を都営三田線にも対応付けた。1番出入口は公式案内に時間制限があるため除外。手動の限定的な照合は `scripts/reviews/official-entrance-associations.json` に記録し、他の共同使用駅へ一般化しない。公式サイトは施設共用と出口の裏付けであり、座標はOSMに由来する。画面から公式案内も開ける。

今回の入口候補1,086ノードとホーム候補894 wayは `scripts/reviews/entrance-connection-ids.json` に固定した。候補であることは採用を意味しない。18回の直列取得で歩道2,938 way等を保存し、問い合わせ・取得日時・原文SHA-256を `src/data/entrance-coverage.json` に記録した。各入口の日時は資料の取得・照合時点であり、現地測量や当日の営業確認ではない。

```powershell

npm run data:entrances:added
```

- 旧サイトのJR駅一覧、小田急・京急の施設CSVサンプルは、駅代表座標とバリアフリー設備の有無を持つが、入口別の座標ではなかったため入口に転用しない。
- 都営大江戸線13駅の屋内データは既に入口対応している駅が中心で、チャレンジ期間等の提供条件もある。今回の175駅・路線の追加座標には使っていない。
- [東京都の新宿駅周辺施設・歩行ルートGeoJSON](https://www.toshiseibi.metro.tokyo.lg.jp/kotsu_butsuryu/kotsuseisaku/kotsu_suishin/shinjuku_shisetsu)は2023年公開。再開発後の小田急等の入口との現時点の整合を確定できず、そのまま採用しない。
- 京王浜田山の公式構内図、東京都交通局の日暮里・舎人ライナー駅案内、京急・東急・とさでん交通の公式案内等も確認した。構内図に出口があることだけで緯度経度を推測しない。各社全駅の公式構内図を894件手作業で確認したという意味ではない。

残る719駅・路線は、専用入口ノードがない、駅施設との所属・歩道接続がない、他社の駅入口と競合する等により未収録。とさでん交通の路面停留場も入口を生成していない。GPSからの道路経路取得と現地の開閉・横断・改札への接続は別の検証であり、全地点の現地歩行試験は未実施。

最初に追加した西日本各社の時刻表の別公開先は、[西日本データ再調査](western-data-sources-20261025.md)にまとめた。

`src/data/added-entrances.json` は独立したOSM入口の座標・名称・出典・駅施設との対応根拠を持つ。`src/data/entrance-coverage.json` は事業者別件数、取得日時、問い合わせ、原資料SHA-256を持つ。ODPTの認証付き原時刻表、トークン、現在地は含まない。

取り込み条件は `scripts/lib/entrance-match.mjs`。駅名・位置と事業者の整合を確認したうえで、次のいずれかに限定する。

- `stop_area` の明示的な入口メンバー。
- 同名の駅舎、駅施設グループに含まれる駅舎、または該当事業者の同名駅地点を内包する駅舎の外形上の入口ノード。
- 駅名が明記された鉄道入口。競合する他事業者の同名駅や別駅施設への所属があるものは採用しない。

駅中心の座標、単に近い店舗の入口、ホーム中心、ホーム端を駅入口に変換しない。出口専用、私有・顧客専用・許可制、条件付き通行、営業時間付き、閉鎖・工事・臨時・非常用、施錠、一方通行の徒歩入口は除外する。駅ごとの入口を手動で全件現地確認した記録ではなく、上記条件による地図上の照合である。入口から改札・ホームまでの移動、階段や信号、実際の開閉、バリアフリーは別途確認が必要。

[OSMのstop_area](https://wiki.openstreetmap.org/wiki/Tag:public_transport%3Dstop_area) と [駅舎・入口のマッピング](https://wiki.openstreetmap.org/wiki/Railway_stations) を対応付けに使用。© OpenStreetMap contributors / [ODbL](https://www.openstreetmap.org/copyright)。派生入口データもODbLで提供する。画面の「入口の地図情報」「駅との対応根拠」から個別原資料を開ける。

取得・再生成は次の順番で行う。Overpassへの問い合わせは直列のオフライン取得のみ。アプリの現在地取得やカウントダウンからは問い合わせない。

```powershell
npm run data:entrances:fetch
npm run data:entrances:added
npm run data:entrances
```

追加入口の再生成には `.cache/osm/added/` の取得原本と、ローカルの認証付き駅カタログキャッシュが必要。原本ハッシュが変わると停止する。`data:entrances` と従来の `data:rebuild` は関西の入口だけを再生成し、追加入口ファイルを上書きしない。サーバーとクライアントは同じ2ファイルを統合して利用する。

未収録は **894駅・路線**。既存GTFSには入口種別やpathwaysがなく、認証付き8事業者のStationにもexit参照がなかった。とさでん交通の乗り場、都電荒川線周辺、東急世田谷線周辺のホーム・歩道も調査したが、停留場と入口を確実に対応付けられる明示的な接続点は得られなかったため自動生成しない。未収録駅は実測時間の登録を案内する。現在の対応数はアプリの「対応路線とデータ」にも表示する。

### 更新と利用条件

`scripts/reviews/gakuentoshi-entrances.json` は原文 SHA、取得日時、抽出条件、除外理由、確認済み範囲を持つ追加入力。`entrances` 配列は既存入口データと同じ `id / stationId / name / lat / lon / sourceUrl / checkedAt / note` を持つ。再取得時は通常 HTTPS で出口ページと iframe を1回ずつ読み、4マーカーのうち ID 534 / 533 と名称・WGS84 の対応を確認する。本文や座標が変わった場合は自動承認せず再レビューする。画面のカウントダウン時には取得しない。

[駅探利用規約](https://ekitan.com/help/rules/terms) の情報蓄積・加工・再利用に関する条件は別途確認が必要。無料閲覧できることだけを、データベースの複製や再配布の許諾とは解釈しない。今回の入口の個別事実とサイト全体の編集物を区別し、ロゴ・地図画像・デザインはアプリへ転載しない。外部公開・商用配信の許諾を取得済みとは扱わない。
