都営は同名の乗換駅を路線別に数えます。とさでんは東西線・南北線をまたぐ運行を含むため、同じ停留場名の方向別・経路別データをまとめて76件としました。アプリの「対応路線とデータ」に全対応路線、提供者、利用条件、元データ期間、取得日、既存関西11駅の限定範囲を表示します。

採用元は [都営鉄道GTFS](https://ckan.odpt.org/dataset/train-toei) と [とさでん交通路面電車GTFS](https://ckan.odpt.org/dataset/tosaden_traffic_streetcar)。両方ともCC BY 4.0で、出典と加工した旨をアプリ内に記載しています。ZIP内のCSV（GTFS）を正規化しました。

## 未収録と理由

- JR東日本・東京メトロ・首都圏の私鉄各社など、トークンが必要なリソースは今回取り込んでいません。既存の関西11駅の資料は保持しています。
- [函館市電](https://ckan.odpt.org/dataset/hakodate_city_alllines)は2・5系統のデータを取得・変換し、46駅・路線件、乗車可能な停車時刻9,998行をローカルで確認しました。ただし、指定された [GTFS-RU利用条件](https://gtfs-jp.org/GTFS-RUL(ODPT).pdf) は一般公開前の通知・承認を求めています。承認未確認のため `.cache/odpt/hakodate-preview/` のみに保存し、駅検索・公開ディレクトリ・配信バンドルに含めていません。事業者への連絡は行っていません。
- カタログ内の駅ナンバリングPDF等は発車時刻の資料ではないため時刻表へ変換していません。JR貨物のコンテナ時刻表は旅客向け発車案内の対象外です。
- 古いフィードを現行ダイヤに混ぜて件数を増やしていません。未認証・未対応を含む一覧はカタログ監査に残しています。

## 変換と照合

`scripts/import-odpt.py` はPython標準ライブラリのみで動きます。GTFSの `calendar.txt` と `calendar_dates.txt` を適用し、運行日を列挙して収録します。祝日だから日曜ダイヤになるという推測をせず、追加日・除外日を原資料どおりに反映します。元フィードの適用範囲外には拡張しません。

乗車不可・未確定時刻の行は除外します。都営の他社直通境界では、GTFS内の最後の停車駅でも乗車可能な発車を保持しました（1,339行）。通常の方面は次の停車駅で表示し、他社直通境界のみ「他社線への直通方面」と表示します。列車の行先は別に保持します。とさでんの30秒単位の発車も保持し、Webとウィジェットの時刻計算を秒対応にしました。

|元CSVの停車時刻行|元件数|採用件数|乗車不可などの除外|
|---|---:|---:|---:|
|都営|122,798|117,997|4,801|
|とさでん|27,485|26,461|1,024|
|合計|150,283|144,458|5,825|

これはサービス別の各駅停車時刻行数です。列車本数・1日の便数・日付展開後の出力行数とは異なります。

`scripts/verify-odpt.py` はインポーターと別にCSVを読み、駅名・発車時刻・行先の多重集合を比較します。各社について2026-10-23・24・25、11-03、12-31、2027-01-01、適用最終日の計7日、合計14条件で欠落・余分な発車ともゼロでした。出力内の同一発車識別子の重複もゼロです。結果は [原資料との照合](odpt-source-comparison.json)、原ファイルSHA-256・期間・件数は [変換検証](odpt-validation.json) に保存しています。

現地運行・臨時変更・遅延・運休の確認は含みません。提供されたフィードを正確に変換できた範囲の検証です。取得確認から30日を超えた資料、適用範囲外の運行日では既存の仕組みで乗車判定を停止します。

## 駅検索と保存

- 検索未入力時は選択中の駅とお気に入り駅のみ表示します。検索結果は40件ずつ追加表示できます。
- 駅名・路線・事業者・地域・元データの別名を検索できます。全角半角とカタカナ／ひらがなを正規化し、空白区切りはAND検索です。元データに読みがない駅について、漢字の読みを生成・推測していません。
- 行を選ぶ操作と☆によるお気に入り登録を分離しました。☆を押しても現在の乗車駅は変わりません。
- 駅のお気に入りは `stationFavorites` に保存し、既存の駅＋方面のお気に入り、登録地点、設定を保持します。
- キーボードによる検索、結果移動、Tab移動、Escapeで閉じる操作、閉じた後のフォーカス復帰に対応します。

## データ量・オフライン・徒歩判定

追加時刻表は225個の版付きJSON、合計19,605,256バイト（非圧縮）です。駅一覧だけを初期表示に読み込み、時刻表は選択中の駅のファイルだけを取得します。全時刻表をJavaScriptやPWAの事前キャッシュへ詰め込みません。PWAは取得済み駅ファイルを最大16個保存し、未取得駅はオフラインで取得不可と明示します。アプリ更新時にはキャッシュが切り替わるため、各駅をオンラインで開き直してください。

新規駅には駅中心座標がありますが、確認済みの駅入口情報はありません。入口を推測したGPS徒歩判定は行わず、実測徒歩時間を登録する案内を表示します。既存11駅22入口の経路機能は保持します。

## 更新・再現手順

```powershell
# 保持した原資料から再生成（取得日時を新しく見せない）
npm run data:odpt
# 原資料を再取得する場合
npm run data:odpt:refresh
# 原CSVと生成データの独立照合
npm run data:odpt:audit
# カタログ一覧取得（既知の詳細はキャッシュを利用）
npm run data:odpt:catalog
# 既知の詳細ページも再取得する場合
npm run data:odpt:catalog -- --refresh
```

元ZIPとメタデータは `.cache/odpt/`、ハッシュ付きの原ZIPも同じ場所に保持します。使われなくなった生成JSONは `.cache/odpt/retired-generated/` へ退避します。現在の生成物は `src/data/odpt-stations.json`、`src/data/odpt-coverage.json`、`public/data/odpt/` です。将来の函館市電の新しいURLや利用条件変更は自動推測せず、カタログで再確認してからアダプターを更新します。今回のカタログ監査JSONは2026-10-23時点の保存記録であり、上のコマンドが自動で書き換える監査報告ではありません。

npm run build
npx playwright test --config=playwright.pwa.config.ts --workers=2
./native/android/test-logic.ps1
