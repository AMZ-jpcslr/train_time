# JR公開日付指定時刻表の取得記録

2026-10-22に、ユーザー指定の無料公開ページを通常のHTTP GETで読み取り、この端末のローカルプロトタイプ用に発車の事実を抽出した。登録、API契約、支払い、外部問い合わせ、公開デプロイは行っていない。従前の「JR未取得」調査記録は本記録で更新する。

Vercel向けAPIでも同じ日付指定の解析・検証を使用し、正規化キャッシュと取得ロックをRedisで共有します。原資料を一時領域だけで処理する構成と検証範囲は [Vercel公開手順](deployment-vercel.md)、[配信構成の検証](deployment-verification.md) を参照してください。

## 対応範囲

**4駅8方面を運行日ごとに公式ページから取得する方式に更新。** 対象路線への絞り込み後、2026-10-22・23（平日）各1,702便、24（土曜）・25（日曜）各1,577便、32表6,558便を保存した。一日の確認から年間の平日ダイヤへ一般化せず、土曜・日曜も別のURL・表示日・取得証拠を持つ。出典の運行日は午前4時台〜翌午前3時台であり、10月23日0時台の便は10月22日運行日の24時台として保持する。

ローカルAPIの `server/jr-service.mjs` が必要な運行日をオンデマンド取得する。明日は明日の公開時刻表を読み、過去の平日表を転用しない。公開元がまだ掲載していない日付、表示日が要求日に一致しない場合、通信失敗、未知の形式ではその日の表を「取得不可」とし、別日の時刻表で埋めない。毎日使う際は、このローカルAPIを含むアプリサーバーの起動と通信が必要。

## 取得と検証方法

駅IDはユーザー指定の駅ページに対応する西宮0610136、大阪0610130、茨木0610124、南草津0610149。各駅の公開時刻表入口 `https://timetable.jr-odekake.net/cgi-bin/mydia_sp.cgi?MD=3&FN=0&EID=駅ID&date=20261022` の選択日を確認し、路線名・方面名が完全一致するリンクから実際の時刻表IDを解決する。ページ先頭や未知の路線IDを推測で採用しない。

`scripts/import-jr.mjs` はモバイル向け文字表現の各便から時刻、行先、経由、種別、注記、番線を取得する。駅名・方面・路線・選択日の値と文字ラベル・画面本文の表示日・4時始まりの注記を確認し、PC向け表現と始発から終便まで全便の列車リンク、時刻、番線、件数を突合する。未知の条件記号、未知形式、列ずれ、重複、順序不一致、行先欠損は処理を停止し、既存JSONを上書きしない。取得不能時に推測で補完しない。

土日表の既知記号 `◆` は、公式凡例が「表示の月日以外」の運転・行先・時刻変更を警告していることを同じページで確認した場合だけ受け入れ、便の注記に保持する。別日への一般化はしない。10月24日西宮6:12発の[Ａ快速701号](https://timetable.jr-odekake.net/train-timetable/389371?date=20261024)を別途確認し、「土曜・休日運転・但し９月１８～２７日を除く」と指定日の整合も確認した。全ての `◆` 便の詳細ページを取得して運転カレンダーまで個別確認したわけではない。判定の根拠は指定日を表示する駅時刻表であり、急な運休等は含まない。

10月22日は各方面の始発、12時台先頭、終便を元HTMLの文字欄と別途照合し、固定した期待値で再検査した。追加日と今後の日付は、上記の日付・路線照合と全便PC/モバイル整合を通過した表を `verified`（機械検証済）として使用する。人手の固定サンプルレビューと機械検証は `verificationMethod` / `independentlyReviewed` で区別する。元資料が示す改正日は取得した全32方面日 **2026年10月03日**。この値は改正日であり、確認済みの有効期間と混同しない。JSONの `serviceDates / validFrom / validTo` は各表の当該運行日1日のみに限定。`retrievedAt` は実取得時刻、`checkedAt` は当該取得の確認時刻。原HTMLのSHA256、件数、始発・日中・終便の照合証拠は `docs/jr-validation.json`。全列車詳細ページへの個別照合や運行実績確認はしていない。

`普通（京都から快速）` は出発駅での表示種別を丸ごと保持し、別の注記spanにある「うれしート連結」等は便の `notes` に保存する。`米原・敦賀行（湖西線経由）` の複合行先・経由を切り落とさない。個々の行先と「京都・大阪方面」の方面項目は別にする。

## 再実行

```powershell
node scripts/import-jr.mjs --date 2026-10-22
npx vitest run tests/jr.test.ts tests/jr-cache.test.ts tests/jr-service.test.ts
node scripts/verify-jr-scope.mjs
# 当日公開表を改めて取得する必要があるときだけ:
node scripts/import-jr.mjs --date 2026-10-22 --refresh
# --date を省略するとJST 04:00境界の現在運行日
node scripts/import-jr.mjs --refresh
```

通常実行はキャッシュ専用。不足・破損・来歴不一致があれば通信せず `--refresh` を求めて停止する。初回取得または明示更新は `--refresh` を指定し、8表と4駅入口のみ、リクエスト間隔1.2秒。既存キャッシュは `.cache/jr-public/運行日/` を使い、カウントダウンや画面更新では取得しない。キャッシュ再利用で取得日を新しく見せない。各HTMLの `.meta.json` に出典URL・SHA256・実取得時刻を保持し、ファイルmtimeは参照しない。旧時刻表キャッシュは現JSONと検証証拠のURL・SHA256・取得時刻が一致する場合だけ移行する。旧駅入口HTMLは実取得時刻の記録がないため、既存の入口URL・解決先時刻表URLとの一致を確認して `retrievedAt: null` / `kind: legacy-navigation` とローカル照合日時を記録する。これは取得日を復元した記録ではなく、時刻表の鮮度に一切使わない。更新前JSON/HTMLとsidecarは `.cache` 内に保存する。`.cache` はGit対象外かつWeb公開対象外。

他日も日付単位で取得し、上記の機械検証を通過すれば使用できる。10月22日の固定期待値が再取得で不一致なら自動的に通さず差分を調べる。異なる日のデータと検証証拠は削除せず、同じIDの更新だけ置換する。`docs/jr-validation.json` も日付入りIDでマージし、後日の取込で過去日のSHA256・取得時刻を失わない。

### ローカルサーバーからの自動更新

`getJrTimetables('YYYY-MM-DD')` は4駅8方面をまとめて返す。成功時は `status: ready`、`tables`、実取得に基づく `fetchedAt / expiresAt` を返す。失敗時は `status: unavailable`、空の `tables`、`errors / retryAfter` を返す。昨日～31日先に要求を限定する。日付が変われば別のキャッシュキーとなり、その日のURLを取得する。APIは任意外部URLを受け取らない。

- 同日同時要求を1回にまとめ、異なる日の取得も直列化する。
- 原HTMLと正規化済み表を端末の `.cache` に保存。元の取得時刻から6時間は通信せず再利用する。カウントダウンの毎秒更新は取得と独立。
- キャッシュ期限後は再取得。失敗時は15分間バックオフし、再起動しても失敗記録を引き継ぐ。期限切れ表や別日表へ黙って切り替えない。
- 1回の更新は4入口+8方面の通常GET、各リクエスト間1.2秒、タイムアウト20秒。リダイレクト先の日付変更も本文検証で拒否する。
- SHA256・日付・8方面・検証証拠を検査し、正常な全表が揃ってから日別JSONを原子的に置き換える。前版は保存する。路線混入修正後はAPI `schemaVersion: 2`・各表 `scopeVersion: 2` を必須にし、旧版のサーバーキャッシュを原HTMLから再生成した。ブラウザー保存キーも `mania-u:jr-daily:v2` に変更し、旧版が6時間以内でも復活しない。
- 静的ビルドに保存済みの日付があっても、未取得の未来日をオフラインで作り出すことはできない。バックグラウンド常駐の取得ではなく、アプリ利用時の更新。

2026-10-22の追加検証: `tests/jr.test.ts` 23件、`jr-cache.test.ts` 6件、`jr-service.test.ts` 9件、`jr-feed.test.ts` 13件（合計51件）成功。日別実取得を再解析し10/22・23が各1,702便、10/24・25が各1,577便を対象路線として使用。サービスの実データ読み出し、路線除外前後の件数、他駅の直通便保持、未知行先の停止、旧キャッシュ無効化、同時要求・再起動後キャッシュ・期限切れ・日付取り違え・バックオフ・改ざんキャッシュ拒否を検証した。テストの日時/通信障害は合成条件で、運行実績を検証したものではない。

## 利用条件と残る確認事項

[交通新聞社のJR時刻表利用案内](https://www.kotsu.co.jp/jrlogo/) は掲載時刻表について無断転載・複写・加工等の制限を示している。無料で閲覧できることと、データの再配布・公開アプリでの保存再利用が許諾されることは同じではない。今回のユーザー指定に従ったローカルでの事実抽出実装は、契約上の許諾取得や法的確認を完了したという意味ではない。発車の事実、創作的編集・データベース、サイトの利用条件は区別する必要がある。

ソースHTMLのレイアウト、ロゴ、画像、説明文はアプリに転載しない。抽出JSONを含めた一般公開・配布・長期オフライン保存の利用条件は未確認のため、この成果物をそのまま公開する許諾は得ていない。認証やアクセス制限の迂回、高頻度取得は行っていない。PWAに含まれる抽出データの端末キャッシュも、この端末での試作の範囲であり公開ライセンスの確認済みを意味しない。

代替調査では交通新聞社の法人向け[時刻データ販売](https://www.kotsu.co.jp/service/jikoku_solution/data_sales/)、駅すぱあとAPI、NAVITIME APIも確認したが、登録・契約を要しない今回の条件に置き換わる許諾済み全時刻データは確認できなかった。API登録や契約は実施せず、ユーザー指定どおり無料公開ページの読み取りを採用した。
