# モバイル操作・WebKit・種別色の改善（2026-10-23）

対象は `https://train-time-three.vercel.app/`。開始時は main / origin/main とも `6c7fddfee8945f3d40ade6c82035e5321bd6a63e`、未コミット変更なし。既存の計算、時刻表、PWA更新確認、登録地点を維持した。ui-ux-designer / ui-ux-pro-max / frontend-design / scroll-experience の方針に沿い、既存の横カードとネイティブスクロールを改善した。

実機環境がないため代替検証を進める、という利用者の回答を受けて実施。iPhoneやSafari実機、実際の指による操作、ユーザー満足度を検証済みとはしない。実GPSは要求せず、拒否モックと架空の登録地点だけを使用。公開版でも徒歩APIへの通信を遮断した。

## 色の根拠と対応範囲

車体の塗装色ではなく、公式の種別案内色を採用。鉄道会社内でも路線図・駅時刻表・車両表示の色が異なることがあるため、出典を固定した。

|会社・基準|種別|色|
|---|---|---|
|JR西日本・駅時刻表|普通 / 快速 / 新快速 / 特急|`#000000` / `#FF9900` / `#0000FF` / `#FF0000`|
|阪急・神戸線路線案内|普通 / 特急・通勤特急・準特急|`#000000` / `#EA5504`|
|阪急・神戸線路線案内|急行 / 快速 / 準急|`#F6AB00` / `#008CD6` / `#009D6B`|

- [JR西宮の公式時刻表](https://timetable.jr-odekake.net/station-timetable/2801012001?date=20261023)、[南草津](https://timetable.jr-odekake.net/station-timetable/2813013001?date=20261023) の種別と `legendOrange` / `legendBlue` / `legendRed` を照合。[公式色定義CSS](https://timetable.jr-odekake.net/public/css/legend-41c870f6d087154350b22e2ada0bba56.css)。普通は黒文字。A快速、新快速の座席注記、はるか、らくラクびわこを含む。
- [阪急公式路線案内](https://www.hankyu.co.jp/station/index.html)。主サイトの取得失敗時、同社公開ドメインの[案内ページ](https://develop-rail.hankyu.co.jp/station/index.html)と[神戸線凡例画像](https://develop-rail.hankyu.co.jp/station/img/list_rosen_kobe.png)で確認し、画像内の単色領域のRGBを取得した。模式線・模様は再現せず、文字名で細かな種別を区別する。
- 種別名の先頭を照合する。「普通（京都から快速）」は普通色。全角Ａを正規化する。文字列中に「特急」があるだけで他社の「山陽S特急」を阪急特急色にはしない。
- 阪神・市営地下鉄・未確認の種別は共通色 `#727D78`。たとえば[阪神今津の公式凡例](https://www.hanshin.co.jp/search/imazu_u2.pdf)は赤=急行、青=快速急行だが、他駅では直通特急の色が停車パターンも表す。現在データだけでは全種別の色を一意に決められず、今回は統一色の断定を避けた。ここは未完了の対応範囲として残す。

色は細いバッジ帯とアイコンに使い、本文は白背景に濃色文字。補助色だけで判断させない。未確認のバッジにはその旨のtitleを付け、種別名自体は取得した文字を保持。

## 検証方法・環境上の制約

時刻は `2026-10-23T14:00:00+09:00`、contextのtimezoneは `Asia/Tokyo`。新しい操作試験は `page.clock.setFixedTime` によりDateだけ固定し、タイマー・rAF・native smooth scrollは実際に動かす。単純なscrollLeft代入をスワイプの証拠には使わず、Chromium CDPのtouchStart / touchMove / touchEndで左右のジェスチャーを入力した。

Windowsの最新WebKit 27.2はDLLがアプリケーション制御に遮断され起動不可。保護設定は変更しなかった。公式配布のWebKit 26.0 (revision 2215) は動作した。最新ランナーとの混在では `Page.overrideSetting: Unknown setting: PushAPIEnabled` が発生したため、対応するPlaywright 1.56.1を隔離して実行した。通常のChromiumとLinux CIはlockfileのPlaywrightを使う。

旧版の再現手順（先に `npx --yes --package=@playwright/test@1.56.1 playwright install webkit` で入手）：

```powershell
node scripts/test-webkit-compat.mjs <@playwright/test@1.56.1の絶対ディレクトリ> --workers=1
```

コピー先は `.cache/webkit-compat`、出力は `test-results/webkit-compat`。試験内容はtracked sourceから毎回生成する。WebKitではCDPのタッチ入力が使えないため、タッチ専用3枠は明示スキップし、ボタン・キーボード・表示・連動を検証。物理的なSafari操作とは区別する。

初期試験では、innerTextとtextContentの空白差によるテスト失敗、旧エンジンと新ランナーの不整合、WebKitの図更新が遅れる失敗があった。空白比較を揃え、対応するランナーへ分離し、図のフレーム更新を修正した。最終結果は以下に記録する。
