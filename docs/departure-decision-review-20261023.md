## 先に確認した計算定義

現在の仕様は次のとおり。既定値や判定閾値は変更していない。

```text
ここにいられる時間 = 発車予定 − 現在時刻 − 入口までの徒歩時間 − 駅構内時間
出発目安時刻       = 発車予定 − 入口までの徒歩時間 − 駅構内時間
駅構内時間         = 入口からホームへの移動 ＋ 乗車までの余裕（利用者が一体で設定）
```

追加の独立した安全余裕欄はない。旧 `bufferMinutes` は移行処理で廃止されているため、引き忘れ・二重計上とは扱わない。駅構内時間の既定は3分。余裕3分以上は「徒歩で余裕あり」、0以上3分未満は「余裕が少ない」、負は「次の便がおすすめ」。1ミリ秒の負値も間に合う側へ丸めない。

例：固定2026-10-22 14:00 JST、今出川北方面14:08発、徒歩1分、ホーム移動・乗車余裕3分なら、発車まで8分／ここにいられる目安4分／出発目安14:04。修正後はこの内訳も主表示に出す。

## 残った問題と次の改善

1. **P2・実機／支援技術**：主表示のチェックは通ったが、詳細欄には小さい固定px文字が残る。iOS Safari／Android実機、OS文字拡大、VoiceOver／TalkBackで確認し、影響のある箇所から修正する。
2. **P2・再利用の手間**：登録地点は毎回選択する。前回地点の無条件復元は位置誤認につながるため実装していない。「前回の地点を確認して使う」導線の必要性を利用観察で判断する。一本前への戻りも一覧を使用する。
3. **P2・初回表示速度**：静的時刻表を含むJSが大きい。ビルド警告は残る。低速回線での初期表示時間は未測定。測定後、データ分割の効果を確認する。
4. **運用上の制約**：定刻のみ。遅延・運休・臨時変更、入口開閉、混雑、信号、バリアフリー経路、端末時計の正確さは保証しない。現在の出典内容・運行実態の再確認は別の作業。
5. **未検証**：実際の乗車成功、徒歩所要時間の現地測定、利用者の継続率・満足度、全ブラウザ互換性、ネイティブウィジェット実機。未検証を合格とはしていない。
