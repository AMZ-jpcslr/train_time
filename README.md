# まにあう — 次の電車と、歩く時間。

日本語の交通Webアプリです。ローカル試用とVercelへのデプロイに対応するプロトタイプです。**11駅の公開時刻表から次の5本を表示し、現在地から駅入口までの歩行経路で徒歩時間と乗車目安を計算します。** 阪急・今出川の現行掲載を確認し、阪神甲子園を追加しました。JRは曜日を推測せず、選択中の運行日の公式時刻表を取得・更新します。

開発・資料確認日：2026-10-22（Asia/Tokyo）。予定時刻ベースで、遅延・運休・リアルタイム予測は含みません。一般公開、有料契約、アカウント登録、メール送信は行っていません。

現在の収録は11駅58表・11,400発車レコード（JR4日分を含む）、駅入口22点。単体211件、PC／スマートフォン画面50件、PWA1件がすべて成功しています。最新結果は [位置・経路・画面の検証記録](docs/location-routing-validation.md) にまとめています。時刻表とGPSの確認範囲は [検証記録](docs/verification.md)、Vercel対応の結果は [配信構成の検証](docs/deployment-verification.md) にまとめています。

## 使い方

1. 「乗車駅」を押し、検索付きの独自パネルで駅を選んでから方面を選びます。スマートフォンは画面下から開くパネルです。JRは当該運行日の取得状態を表示し、不足分は公式ページから取得します。
2. **画面上部の「現在地を更新」**を押してブラウザーの位置情報を許可します。ここで初めて現在地を取得し、選択した駅入口への徒歩経路を計算します。
3. 「歩いて向かう駅入口」を確認します。近い入口を先頭にしますが、全入口の最短経路比較ではありません。別の入口にも切り替えられます。
4. 道路経路の距離・徒歩時間、駅構内移動・安全余裕の合計、次の5本の乗車目安を表示します。徒歩時間を手入力する必要はありません。先発について「今の場所にいられる目安：あと○分○秒」と出発する時刻の目安も表示します。登録地点を選んだ場合は、その地点名と実測徒歩時間で計算します。
5. 「徒歩・乗車余裕の設定」で歩行速度（1〜6km/h）、入口からホームまでの時間、安全余裕を調整します。☆で駅・方面を保存できます。

位置情報が使えない場合は「登録地点の実測時間を使う」を展開すると、従来の実測時間も明示的に選択できます。自宅・会社・駅入口を推測して初期登録しません。登録地点は駅に結び付けて端末内に保存し、選択時はその場所にいることを確認してください。

現在地と駅入口の座標を、アプリのAPI経由で **FOSSGISの歩行経路サーバー**へ送ります。現在地履歴はアプリのディスクやlocalStorage、Redisに保存しません。経路はメモリーで10分キャッシュし、提供先ではアクセスログに記録されます。登録地点・お気に入り・設定・取得済みJR日別表は端末内保存です。位置情報の送信先と連絡先を画面に表示します。

「時刻指定プレビュー」は運行日・発車予定の確認用です。指定時刻であることを画面に表示します。**データの鮮度判定と位置情報の鮮度には実時計を使います。** 過去日時へ切り替えても古いデータを有効に戻しません。端末時計の正確さは利用の前提です。

## JRの毎日の更新

`GET /api/jr?date=YYYY-MM-DD` が、指定運行日の4駅8方面を取得します。公式の選択日と本文表示日、駅・路線・方面、PC版／スマートフォン版の全便時刻・番線を照合し、件数・順序・欠損・重複を検査します。大阪西方面の原表には宝塚線行先も混在するため、原表の全件照合の後に対象外を除外し、その件数を証拠に残します。

- 1日分を年間の平日・土休日パターンに転用しません。`serviceDates` と適用開始・終了を当該1日に限定します。
- 取得から6時間以内はキャッシュ。同じ日の同時要求を集約し、異なる日の外部取得も直列化、通常要求間隔1.2秒。失敗後15分は再取得を抑えます。
- 運行日が04:00 JSTに変わると、その日を取得します。画面復帰や保存データの6時間期限到達時も再確認します。ブラウザー終了中に常駐取得はしません。
- 日付不一致・検証不合格・取得失敗で、別日の表を代用しません。通信断の場合だけ6時間以内の同日保存データを明示して表示し、期限後は徒歩判定を停止します。
- 先の日程は現在運行日から31日以内で、元サイトに公開されている日付が対象です。先のダイヤを予測生成しません。
- 端末に最大5日分を保存。保存できなくても現在画面ではメモリー内の取得結果を使えます。ローカルサーバーの原資料と正規化キャッシュは `.cache/` 内。Vercelでは正規化キャッシュをRedisに共有し、原資料の処理は一時フォルダー内で完結します。

## 徒歩時間と判定

FOSSGISの**徒歩用道路グラフ**を使用し、各経路ステップもwalkingであることを検証します。距離・所要秒数・経路形状・端点のずれを検査し、自動車ルートを徒歩へ換算しません。現在地・入口から200m以内の道路接続候補を1回の要求で探索します。道路までの接続が30mを超える場合は、接続区間を直線で加えた概算時間を表示し、乗車判定と滞在時間の目安は停止します。200m以内でも道路が見つからない、または両端を結べない場合は理由を表示します。

`徒歩分 = ceil(max(提供所要秒数 × 4.5 / 設定速度, 経路距離 ÷ 設定速度) / 60)`（単位換算を含む）。歩行プロファイルの既定速度4.5km/hに対して設定速度を反映し、道路距離による時間を下回らないようにします。端点の補正距離も加えます。階段・信号・混雑・工事・入口開閉による実時間を保証するものではありません。

`余裕 = 発車予定 − 現在時刻 − 徒歩時間 − 駅構内移動 − 安全余裕`。余裕3分以上は「徒歩で余裕あり」、0〜3分未満は「余裕が少ない」、負なら「次の便がおすすめ」。秒単位の負の余裕を丸めて乗れる扱いにしません。出発する目安は切り捨て分です。「今の場所にいられる目安」は同じ式を使い、秒を切り捨てて表示します。目安ちょうど／過ぎた場合は専用の文言に切り替え、負の余裕を0分滞在可能とは扱いません。画面復帰時も現在時刻で再計算します。

11駅22入口を収録。OSM20点と、学園都市の公開出口地図2点を使います。駅中心は近隣駅の並び替えだけに使用。入口の開閉・現地測量・バリアフリーは網羅未確認です。大きな駅の構内時間は実際に使うホームに合わせて調整してください。

位置が5分超・精度100m超・不正な位置、経路取得中・失敗・オフラインは自動徒歩判定不可です。駅や入口の切替中に前の経路を流用しません。位置取得は高精度を要求する最大20秒のwatch方式で、精度を満たしたら終了します。取得中に外部経路要求は行わず、中止・画面離脱時にwatchを停止します。現在地を更新すれば改めて取得します。走行の試算・駆け込み乗車の推奨はありません。

経路サービスは少人数の試用を想定し、1.1秒以上の間隔、30回/時・120回/日、10分キャッシュ、混雑時バックオフ、帰属・修正リンク・連絡先表示を実装しています。ローカルでは起動プロセス内、VercelではRedisを使って全インスタンスで上限を共有します。待機中を含む要求は1プロセス8件、外部応答は2MiBまでに制限しています。本番の無制限APIではありません。条件・出典・位置の扱いは [徒歩経路仕様](docs/routing.md)、[入口資料](docs/entrance-sources.md)、[Vercel公開手順](docs/deployment-vercel.md) を参照してください。

経路取得失敗時は「徒歩経路を再取得」から明示的に再試行できます。「Googleマップで徒歩経路を見る」は現在地と入口を渡してGoogleの徒歩経路を開くリンクです。クリックまでGoogleへ位置を送らず、Googleが算出した所要時間はアプリへ読み戻しません。課金API・APIキーは使用していません。

## 日付とその他の時刻表更新

時刻はAsia/Tokyo、運行日は04:00〜翌03:59。0時台は24時台へ正規化します。祝日は[内閣府公式CSV](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)の1955〜2027年を収録。対象年外は不明として扱います。年末年始12/29〜1/3は、確認できる日付限定表がない限り通常パターンで判定しません。

JR以外は確認日から30日をアプリの再確認期限とします。事業者の適用期間・保証期間・ライセンス期間とは別です。出典ページの取得日時、確認日時、適用期間、改正日、検証状態を保存し、キャッシュの再解析だけで確認日を更新しません。

```powershell
# JR: 日付省略なら現在運行日。初回/更新は --refresh
npm run data:jr -- --refresh
npm run data:jr -- --date 2026-10-24 --refresh

# 神戸の公式CSVと祝日更新
npm run data:update
# 公開資料を明示的に再取得し検証
npm run data:kyoto -- --refresh
npm run data:hankyu -- --refresh
npm run data:hanshin -- --refresh

# 保存原資料の再解析（通信なし）
npm run data:rebuild
npm run data:entrances

# データを同梱し直す場合
npm run build
```

新しくcloneした環境に原資料キャッシュはありません。`data:rebuild` は取得した人の端末にある原資料を再解析するためのコマンドです。初回取得は各取得コマンドの `--refresh` が必要で、サイト側の取得制限等により成功しない場合があります。GitHub/CIには原HTML・PDFを同梱しません。

原資料は `.cache/municipal/`、`.cache/jr-public/`、`.cache/jr-service/`、`.cache/kyoto/`、`.cache/hankyu-web/`、`.cache/hanshin/`、`.cache/osm/` 等へ保存し、Git・Web配信から除外。更新前資料は履歴として保持します。取得失敗や未知の版・記号・固定照合値の変化は停止／partialにし、数字を推測して補いません。阪急の通常HTTPSが失敗する場合、閲覧サービスで取得した保存テキストを再解析できますが、元サーバーのHTTP取得成功とは区別します。

## PWAと将来の構成

ビルド単位のService Workerでアプリ・同梱時刻表を保存します。初回オンライン準備後はオフライン起動できますが、新しい日付の時刻表取得・徒歩経路計算には通信が必要です。取得済みJRも6時間、その他の時刻表も30日の期限を超えると停止します。新ビルドのSWは、通常は全タブを閉じて開き直すと有効になります。

ホーム画面追加は**ネイティブウィジェットではありません**。Android/iOSアプリ、常駐取得、ネイティブウィジェットは未実装。スマートフォンでのGPS/PWAには通常HTTPSが必要で、PCのHTTP LANアドレスへ接続するだけで使えるとは限りません。一般公開デプロイや証明書設定は今回行っていません。

```text
src/domain/       時刻・運行日・判定・位置品質・保存・経路境界
src/data/         時刻表・祝日・駅・入口
src/use*.ts       日付別更新／経路取得と画面状態の接続
api/              VercelのFunction入口
server/           共通API、ローカル／Vercelの日次取得・徒歩・共有制限
scripts/          再取得・解析・照合・PWA生成
tests/            単体・E2E・PWA
docs/             出典・検証証拠・履歴・画面画像
```

このフォルダーは独立したGitリポジトリです。親ディレクトリ内の他プロジェクトは変更していません。GitHubへはソース・正規化データ・検証記録を保存し、秘密情報・原資料・ローカル画面画像は除外します。Vercel側のデプロイは利用者が行います。
