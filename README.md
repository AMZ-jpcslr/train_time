## 使い方

1. 最初の「出発判断」で、駅・方面・対象列車・発車時刻・ここを出る時刻の目安を確認します。駅名または下部の「駅・方面」を押し、駅名・路線・事業者・地域で検索して駅を選びます。未入力時は選択中の駅とお気に入り駅だけを表示します。検索結果の☆は駅を切り替えずにお気に入り登録でき、40件ずつ追加表示できます。スマートフォンは画面下から開くパネルです。JRの時刻表取得に対応した既存4駅では当該運行日の取得状態を表示し、不足分は公式ページから取得します。新しい検索専用駅は時刻表未対応と表示し、公式サイトで確認する導線を出します。ODPT追加駅は選んだ駅の時刻表だけを読み込みます。
2. **画面上部の「現在地を更新」**を押してブラウザーの位置情報を許可します。ここで初めて現在地を取得し、選択した駅入口への徒歩経路を計算します。
3. 「歩いて向かう駅入口」を確認します。近い入口を先頭にしますが、全入口の最短経路比較ではありません。別の入口にも切り替えられます。
4. 道路経路の距離・徒歩時間、駅構内移動・安全余裕の合計、各便の乗車目安を表示します。徒歩時間を手入力する必要はありません。選択した電車について「ここを出る目安：HH:mmまで」と「あと○分」を表示します。秒単位の判定は維持し、秒カウントは表示しません。登録地点を選んだ場合は、その地点名と実測徒歩時間で計算します。
5. 「一本後を選ぶ」で表示候補内の次の電車に変更できます。主表示の「計算条件」または下部の「徒歩時間」から、歩行速度（1〜6km/h）と入口からホームまでの時間を調整できます。乗車までの余裕はこの構内時間に含め、別枠の加算はありません。☆で駅・方面を保存できます。

位置情報が使えない場合は、上部の「実測時間を使う」から登録地点の選択・入力を開けます。「登録地点の実測時間を使う」を展開しても、従来の実測時間も明示的に選択できます。自宅・会社・駅入口を推測して初期登録しません。登録地点は駅に結び付けて端末内に保存し、選択時はその場所にいることを確認してください。

現在地と駅入口の座標を、アプリのAPI経由で **FOSSGISの歩行経路サーバー**へ送ります。現在地履歴はアプリのディスクやlocalStorage、Redisに保存しません。経路はメモリーで10分キャッシュし、提供先ではアクセスログに記録されます。登録地点・お気に入り・設定・取得済みJR日別表は端末内保存です。位置情報の送信先と連絡先を画面に表示します。

「時刻指定プレビュー」は運行日・発車予定の確認用です。指定時刻であることを画面に表示します。**データの鮮度判定と位置情報の鮮度には実時計を使います。** 過去日時へ切り替えても古いデータを有効に戻しません。端末時計の正確さは利用の前提です。

入口未収録のODPT追加駅と今回追加した神戸駅では、上のGPSによる徒歩計算は使いません。「実測時間を使う」から、その駅までの実測徒歩時間を登録してください。時刻表の閲覧と実測時間による判定に対応しています。

## JRの毎日の更新

`GET /api/jr?date=YYYY-MM-DD` が、指定運行日の4駅8方面を取得します。公式の選択日と本文表示日、駅・路線・方面、PC版／スマートフォン版の全便時刻・番線を照合し、件数・順序・欠損・重複を検査します。大阪西方面の原表には宝塚線行先も混在するため、原表の全件照合の後に対象外を除外し、その件数を証拠に残します。

- 1日分を年間の平日・土休日パターンに転用しません。`serviceDates` と適用開始・終了を当該1日に限定します。
- 取得から6時間以内はキャッシュ。同じ日の同時要求を集約し、異なる日の外部取得も直列化、通常要求間隔1.2秒。失敗後15分は再取得を抑えます。
- 運行日が04:00 JSTに変わると、その日を取得します。画面復帰や保存データの6時間期限到達時も再確認します。ブラウザー終了中に常駐取得はしません。
- 日付不一致・検証不合格・取得失敗で、別日の表を代用しません。通信断の場合だけ6時間以内の同日保存データを明示して表示し、期限後は徒歩判定を停止します。
- 先の日程は現在運行日から31日以内で、元サイトに公開されている日付が対象です。先のダイヤを予測生成しません。
- 端末に最大5日分を保存。保存できなくても現在画面ではメモリー内の取得結果を使えます。ローカルサーバーの原資料と正規化キャッシュは `.cache/` 内。Vercelでは正規化キャッシュをRedisに共有し、原資料の処理は一時フォルダー内で完結します。

## 徒歩時間と判定

FOSSGISの**徒歩用道路グラフ**を使用し、各経路ステップもwalkingであることを検証します。距離・所要秒数・経路形状・端点のずれを検査し、自動車ルートを徒歩へ換算しません。現在地・入口から200m以内の道路接続候補を1回の要求で探索します。道路までの接続が30mを超える場合は、接続区間を直線で加えた概算時間を表示し、乗車判定と滞在時間の目安は停止します。200m以内でも道路が見つからない、または両端を結べない場合は理由を表示します。

`徒歩分 = ceil(max(提供所要秒数 × 4.5 / 設定速度, 経路距離 ÷ 設定速度) / 60)`（単位換算を含む）。歩行プロファイルの既定速度4.5km/hに対して設定速度を反映し、道路距離による時間を下回らないようにします。端点の補正距離も加えます。階段・信号・混雑・工事・入口開閉による実時間を保証するものではありません。

`余裕 = 発車予定 − 現在時刻 − 徒歩時間 − 入口からホームまでの時間`。入口からホームまでの既定3分に乗車までの余裕を含めます。追加の安全余裕は加算しません。旧設定の`bufferMinutes`は読み飛ばし、他の設定・登録地点・お気に入りは保持します。余裕3分以上は「徒歩で余裕あり」、0〜3分未満は「余裕が少ない」、負なら「次の便がおすすめ」。秒単位の負の余裕を丸めて乗れる扱いにしません。

取得済みの同一運行日全便それぞれに「今の場所にいられる目安」を表示します。列車カードの「この電車を選ぶ」を押すと、その便の発車までの時間・判定・出発時刻を大きく表示します。先の便を選んだ後に先発が発車しても選択を保ち、選んだ便が発車済み、時刻表から消失、駅・方面・運行日・プレビュー変更の場合は選択を解除します。秒は切り捨て、出発目安ちょうど／過ぎた場合は専用の文言に切り替えます。画面復帰時も現在時刻で再計算します。

11駅22入口を収録。OSM20点と、学園都市の公開出口地図2点を使います。駅中心は近隣駅の並び替えだけに使用。入口の開閉・現地測量・バリアフリーは網羅未確認です。大きな駅の構内時間は実際に使うホームに合わせて調整してください。

位置が5分超・精度100m超・不正な位置、経路取得中・失敗・オフラインは自動徒歩判定不可です。駅や入口の切替中に前の経路を流用しません。徒歩応答は要求した出発地点と1m以内で一致すること（サーバーの座標丸めを許容）、取得時刻が未来30秒以内・取得後10分未満であることも確認し、不一致や期限切れでは判定を停止します。位置取得は高精度を要求する最大20秒のwatch方式で、精度を満たしたら終了します。取得中に外部経路要求は行わず、中止・画面離脱時にwatchを停止します。現在地を更新すれば改めて取得します。走行の試算・駆け込み乗車の推奨はありません。

経路サービスは少人数の試用を想定し、1.1秒以上の間隔、30回/時・120回/日、10分キャッシュ、混雑時バックオフ、帰属・修正リンク・連絡先表示を実装しています。ローカルでは起動プロセス内、VercelではRedisを使って全インスタンスで上限を共有します。待機中を含む要求は1プロセス8件、外部応答は2MiBまでに制限しています。本番の無制限APIではありません。条件・出典・位置の扱いは [徒歩経路仕様](docs/routing.md)、[入口資料](docs/entrance-sources.md)、[Vercel公開手順](docs/deployment-vercel.md) を参照してください。

経路取得失敗時は「徒歩経路を再取得」から明示的に再試行できます。「Googleマップで徒歩経路を見る」は現在地と入口を渡してGoogleの徒歩経路を開くリンクです。クリックまでGoogleへ位置を送らず、Googleが算出した所要時間はアプリへ読み戻しません。課金API・APIキーは使用していません。

## 日付とその他の時刻表更新

時刻はAsia/Tokyo、運行日は04:00〜翌03:59。0時台は24時台へ正規化します。祝日は[内閣府公式CSV](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)の1955〜2027年を収録。対象年外は不明として扱います。年末年始12/29〜1/3は、確認できる日付限定表がない限り通常パターンで判定しません。

JR以外は確認日から30日をアプリの再確認期限とします。事業者の適用期間・保証期間・ライセンス期間とは別です。出典ページの取得日時、確認日時、適用期間、改正日、検証状態を保存し、キャッシュの再解析だけで確認日を更新しません。

```powershell
# JR: 日付省略なら現在運行日。初回/更新は --refresh
npm run data:jr -- --refresh
npm run data:jr -- --date 2026-10-24 --refresh

# 神戸の公式CSVと祝日更新
npm run data:update
# 公開資料を明示的に再取得し検証
npm run data:kyoto -- --refresh
npm run data:hankyu -- --refresh
npm run data:hanshin -- --refresh

# 保存原資料の再解析（通信なし）
npm run data:rebuild
npm run data:entrances

# データを同梱し直す場合
npm run build
```

新しくcloneした環境に原資料キャッシュはありません。`data:rebuild` は取得した人の端末にある原資料を再解析するためのコマンドです。初回取得は各取得コマンドの `--refresh` が必要で、サイト側の取得制限等により成功しない場合があります。GitHub/CIには原HTML・PDFを同梱しません。

原資料は `.cache/municipal/`、`.cache/jr-public/`、`.cache/jr-service/`、`.cache/kyoto/`、`.cache/hankyu-web/`、`.cache/hanshin/`、`.cache/osm/` 等へ保存し、Git・Web配信から除外。更新前資料は履歴として保持します。取得失敗や未知の版・記号・固定照合値の変化は停止／partialにし、数字を推測して補いません。阪急の通常HTTPSが失敗する場合、閲覧サービスで取得した保存テキストを再解析できますが、元サーバーのHTTP取得成功とは区別します。

## 出典・利用条件の境界

神戸市交通局の[地下鉄オープンデータ](https://kotsu.city.kobe.lg.jp/company/overview/open-data/subway-opendata/)はCC BY 2.1 JPで加工利用。海岸線や神戸市バスのデータと取り違えていません。OSMの道路・入口はODbLに基づき帰属を表示しています。

**無料閲覧と保存・加工・再配布の許諾は別です。** 個々の発車事実、編集・データベース、契約条件を区別します。JR・阪急・駅探等で再利用制限の記載を確認しており、今回のローカル取得・保存・継続利用や公開再配布に関する許諾が解決済みとは判断していません。利用者の依頼に基づくローカルの事実抽出実装で、原サイトのデザイン・ロゴ・画像をアプリへ複製していません。サイトの制限・認証を迂回せず、有料登録や問い合わせ送信も行っていません。一般公開・配布用の権利確認済み成果物ではありません。

- [JR：日付別取得・宝塚線除外・検証](docs/jr-sources.md)
- [阪急：現行公式導線・版情報・照合](docs/hankyu-sources.md)
- [今出川：現行リンクと掲載日・改正日の区別](docs/kyoto-sources.md)
- [阪神甲子園：公式PDF・公開HTML照合と制約](docs/hanshin-sources.md)
- [神戸のCSVとライセンス](docs/municipal-sources.md)
- [ODPT候補・期間限定データの調査](docs/additional-sources.md)

関西の初期取り込みではODPTの登録・API契約を使っていません。京都CSVポータルはメンテナンスに転送され、現行HTMLを採用しました。2026-10-24追加の首都圏データは上記の認証付きODPT APIを使用します。臨時便・野球開催時の増発／臨時停車・特別運行・遅延・運休の網羅は対象外です。

## テストと実画面

```powershell
npm test
npx playwright install chromium
npm run test:e2e
npm run test:pwa
```

CIは合成HTML/CSVと保存済みの正規化データ・検証記録を使う回帰テストです。公式サイトの現時点の内容を再取得・再照合する処理ではありません。テスト・ビルドでは外部時刻表や経路サービスを呼び出しません。

解析、出典検証、祝日、深夜、04:00境界、発車直前、終電後、期限切れ、日付切替、取得失敗、位置拒否・精度・鮮度、歩行モード・距離異常、駅変更中の経路の扱い、端末保存をテストします。PC1280×720・スマートフォン390×664相当のChromiumで実画面を確認し、PWAのオフライン起動も別テストで検証します。

実経路APIは公開駅近傍の検証用座標で疎通確認。E2Eの位置と経路応答は固定して再現可能にし、本人の実位置・実測歩行時間とは区別しています。iPhone/Safari/Androidの実機、実際の乗車成功、バリアフリー経路の検証ではありません。実行結果・件数・スクリーンショットは [検証記録](docs/verification.md)、実経路の成功と失敗は [経路疎通記録](docs/routing-live-validation.json) に保存しています。

## ホーム画面追加・ウィジェット・共有プレビュー

ビルド単位のService Workerでアプリ・同梱時刻表を保存します。初回オンライン準備後はオフライン起動できますが、新しい日付の時刻表取得・徒歩経路計算には通信が必要です。取得済みJRも6時間、その他の時刻表も30日の期限を超えると停止します。

オンラインで画面を開くと公開先のHTMLを確認し、通信できない場合は取得完了済みのオフライン版を使います。更新確認欄はページ下部にあります。新しい版を取得すると画面下端にポップアップを表示し、タップすると更新欄まで自動スクロールします。そこで「最新版に更新」を押すと適用します。ポップアップは閉じることもでき、「アプリの更新を確認」から手動確認も可能です。更新時も登録地点・お気に入り・設定を保持します。初期版のcache-first更新待ち問題は、旧キャッシュから一度だけ自動移行する処理で修正しました。Vercelへデプロイ成功後も画面が変わらない場合は、オンラインで一度再読み込みしてください。修正の再現試験は[PWA更新の検証](docs/pwa-update-fix.md)を参照してください。

画面の「ホーム画面に追加」からインストール案内を開けます。Androidの対応ブラウザでは利用者の操作でインストール確認を呼び出し、iPhoneではSafariの共有メニューから追加する手順を表示します。PWAの追加とネイティブウィジェットは別の機能です。駅・入口・登録地点はすべて独自デザインの選択パネルで、検索・キーボード操作・フォーカス復帰・スマートフォンのタッチ操作に対応しています。

ウィジェットとホストアプリの試作コードを`native/`に収録しています。Android版は不具合報告を受け、READMEでの利用案内を停止しています。**VercelのWeb更新だけでスマートフォンのウィジェットがインストールされることはありません。** [iPhoneの導入](native/ios/README.md)、[機能・検証の境界](docs/mobile-widgets-and-sharing.md)を参照してください。iPhoneはMacとXcodeでのビルド・署名・実機確認が必要で、このWindows環境ではSwiftコンパイル・XCTest・実機導入を実行していません。

Android開発版のReleasesも、不具合修正が終わるまで下書きへ戻しています。公開APKのダウンロードは停止中です。Webアプリの「いつもの駅・方面」は画面上部に配置しています。アプリの更新確認はページ下部にあります。

ネイティブアプリで「選んだ電車をウィジェットに保存」を押すと、最大5本の時刻・選択便・徒歩時間を保存します。現在地の座標はウィジェット保存データに含めません。保存便が発車済み、または時刻表確認期限が切れたらアプリで再保存してください。ウィジェット自身による日々の時刻表自動取得は未実装です。

背景の位置更新は専用アプリ本体で任意ONにできます。Androidは常駐通知と停止ボタン、iPhoneは段階的な位置権限と背景更新スイッチを使います。初期状態・アプリ再起動後はOFFで、登録地点ではGPS更新しません。画面を閉じたブラウザ/PWAの常時GPS取得には対応できません。専用アプリでもOS・省電力・強制終了によって停止するため、常時更新を保証しません。APIの無料試用枠を共用し、位置5分・経路10分・時刻表期限を超える徒歩判定を継続しません。

公開URLは [https://train-time-three.vercel.app/](https://train-time-three.vercel.app/) です。JavaScriptを実行しない共有サービスにも読めるよう、ビルド時にHTMLへdescription、Open Graph、Twitterカードと絶対URLを挿入し、`public/og-image.png`（1200×630）を配信します。既定はこの公開先、環境変数`APP_ORIGIN`、Vercelの`VERCEL_PROJECT_PRODUCTION_URL`の順で明示設定を優先します。画像再生成は`node scripts/render-social-card.mjs`、通常のbuildは外部取得せず同梱PNGを使います。LINE等の共有先に残った古いプレビューは、提供先のキャッシュ更新後に反映されます。
